# Bundled native diff document (presentation only)

The **only** shared production-code exception in gabCode is this read-only Monaco document and its bundled assets. Git/filesystem reads, snapshot coherence, request generation, origin validation, native unavailable/Retry state, lifecycle, preferences, keyboard focus and packaged resources belong independently to Windows and macOS. This directory is not a web application, network service, shared native client/core, or generic extension bridge.

## Reproducible asset build

From this directory: `npm ci --no-audit && npm run build && npm test`. Requires installed Node/npm; no runtime network connection is used by `dist/`. `package-lock.json` pins Monaco Editor **0.57.0** (MIT) and esbuild **0.28.2** (MIT). `npm ci` validates the lock against the package spec. `dist/` and `node_modules/` are generated/ignored; each native target packages an identical clean build output (not its npm build tools) and verifies `dist/manifest.json`. This bundle contains its own HTML, Monaco code/CSS, JSON/CSS/HTML/TypeScript and generic editor worker, common basic language support, and Monaco/DOMPurify/Marked license and upstream third-party notices (with build-time esbuild MIT provenance in the lockfile). No CDN or localhost server. Check `dist/manifest.json` for per-file SHA-256 and size. `npm run build` replaces only this package's generated directory, rejecting a symlink.

`src/index.html` sets a restrictive packaged-page CSP: Monaco injects layout/theme CSS so `style-src` permits inline styles; its worker loader creates a same-origin blob bootstrap, so `worker-src` permits `self blob:` while external scripts, network and navigation remain restricted. No untrusted HTML is inserted. Hosts must additionally restrict their page origin, navigation, subframes, resource mapping and message origin; a page CSP alone does not protect a native bridge. Untrusted code, path and labels enter Monaco model values or DOM text attributes, never HTML. `src/bridge.mjs` validates only presentation snapshot data, selection-scoped `mode` (`side-by-side`/`inline`/`file`), `change` (`next`/`previous`), `find`, `focus` and conditional `deletion` controls, and minimal viewer readiness/failure/progress events. It is not native host validation or a runtime client/core protocol. The concrete schema is `snapshot` with `generation` (nonnegative safe integer), `identity` (nonempty string, max 512 chars), `path` (max 4096), `before` and `after` (each at most 1M UTF-16 code units), `beforeLabel`/`afterLabel` (max 256), `mode` (`side-by-side`, `inline`, `file`), and `beforeFacts`/`afterFacts` (`bom` bool, `eol` one of LF/CRLF/CR/mixed/none, `finalNewline` bool). No file paths are opened from the viewer; reject unknown keys, untrusted origins and stale generations in **each** native host before calling `window.gabCodeViewer.show(...)` with its serialized validated pair. The viewer reports only `ready`, bounded `failure`, or bounded `progress` (active generation and identity; zero-based empty or one-based change index/total, description ≤256 chars, current mode, and conditional File-mode deletion action availability). Each native host validates origin, exact shape and current generation/identity before using progress for its own toolbar; no Git/file/write/navigation requests.

SH-003 adds a read-only Monaco diff editor for Side by side / Inline and a read-only Monaco editor for the full resulting File. The same Monaco diff computation supplies change locations and File gutter markers; boundary deletions expose a conditional native keyboard action to jump to Inline. Native hosts own the one visible change-navigation toolbar and readable position; the embedded live text status remains screen-reader accessible without a second button row or light strip. Preserve the active line and text focus (when the code had focus) on snapshot refresh, or the nearest surviving line on mode switches; explicit BOM/EOL/final-newline facts remain visible even when Monaco normalizes the same text. The native host owns mode preference, invoking-control focus and selected generation. A node-test pass proves projections/schema/asset integrity, not target accessibility; the focused Windows WPF host test checks mode/model rendering, while target-Windows/macOS packaged/offline and screen-reader qualification remains NOT CHECKED — human validation pending.
